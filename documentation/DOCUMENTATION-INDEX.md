## Learning Path for Beginners

### Step 1: Understand the Landscape (1-2 hours)
1. Read [Industry Keywords & Terminology](./Full-Stack-Development-Industry-Keywords.md)
   - Focus on sections relevant to your experience level
   - Note unfamiliar terms for later reference

2. Read [Agent-Native AI Explained](./Agent-Native-AI-and-Droid-Explained.md)
   - Understand the fundamental difference from traditional AI tools
   - Grasp the autonomous execution concept

### Step 2: Install and Explore (30 minutes)
1. Install Droid:
   ```bash
   curl -fsSL https://app.factory.ai/cli | sh
   droid
   ```

2. Read [Complete Guide Summary](./Droid-Complete-Guide-Summary.md)
   - Focus on installation and basic commands
   - Try simple example prompts

### Step 3: Master Communication (2-3 hours)
1. Study [Prompt Engineering Guide](./Prompt-Engineering-for-Factory-Droid.md)
   - Practice the CLEAR framework
   - Try different prompt patterns
   - Start with small, specific requests

### Step 4: Build Your First Feature (1-2 hours)
1. Choose a simple feature for your existing project
2. Apply prompt engineering techniques
3. Review Droid's implementation
4. Iterate based on results

## Quick Reference Cards

### Essential Commands
```bash
# Start Droid
droid

# Specification mode for complex features
droid --spec "feature description"

# Custom Droid usage
droid --droid <droid-name> "task"

# Chat with repository
droid exec "question about codebase"
```

### Effective Prompt Template
```
Context: [Project background and constraints]
Requirements: [Specific, detailed what needs to be built]
Patterns: [Reference existing files/approaches]
Success: [How to verify the implementation works]
```

### Common Patterns
- **Features**: "Build X with requirements A, B, C following pattern in file Y"
- **Bugs**: "Fix error Z occurring in file X when condition happens"  
- **Refactoring**: "Improve structure in module Y while maintaining compatibility"

## Troubleshooting Quick Guide

### Issues & Solutions
| Problem | Solution |
|---------|----------|
| Droid misunderstands | Be more specific, provide existing examples |
| Code style mismatch | Update AGENTS.md or reference exact patterns |
| Feature incomplete | Define comprehensive success criteria |
| Performance problems | Request specific optimizations |
| Security concerns | Use security-focused custom droid |

### When to Use Specifications
Use `--spec` flag for:
- Complex features with multiple components
- Architecture changes
- Features requiring database changes
- Security-sensitive implementations
